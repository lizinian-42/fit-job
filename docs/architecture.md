# Fit Job 苍穹平台技术架构

## 1. 架构原则

1. **平台优先**：正式业务运行在金蝶 AI 苍穹平台，不建设独立 React 主站。
2. **模型优先**：能由表单、流程、服务、报表、权限模型完成的能力，不先写自定义代码。
3. **KWC 补强**：只有低代码控件难以表达的复杂交互和可视化才使用 KWC。
4. **Java 确定性**：评分、状态校验、风险规则、聚合和平台插件由 Java 负责。
5. **AI 可解释**：Agent 负责语义能力，关键结果必须可追踪、可引用、可复核。

## 2. 分层职责

### 2.1 体验层

- 标准页面：苍穹低代码表单、列表、过滤、操作、审批和权限控制；
- 复杂页面：KWC 组件嵌入苍穹页面；
- 统一主题：颜色、字号、间距、状态和图表语言遵循 `docs/design-system.md`。

### 2.2 模型层

- 表单模型：学生、简历、岗位、申请、日志、评价、就业去向、政策；
- 服务模型：匹配、诊断、面试训练、政策检索、风险计算、统计聚合；
- 流程模型：实习申请、多角色审批、异常处理、评价归档；
- 报表模型：就业率、行业、薪资、重点帮扶、实习质量；
- 权限模型：学生、辅导员、企业 HR、院系管理员的数据域和操作权。

### 2.3 Java 扩展层

优先采用苍穹官方生成的 Java 插件或服务工程：

- 表单/操作插件：字段联动、提交前校验、状态迁移；
- 服务插件：六维匹配、风险评分、AI 调用封装；
- 数据聚合：驾驶舱指标、就业质量报告；
- 审计与幂等：调用日志、重试、结果校验、重复提交防护。

独立 Spring Boot 微服务不是默认前提。只有在赛题规则、目标环境和部署方式明确允许，且苍穹插件无法满足时才引入。

### 2.4 AI 能力层

| Agent | 主要输入 | 主要输出 | 确定性护栏 |
| --- | --- | --- | --- |
| 简历诊断 | 学生档案、简历、目标岗位 | 优势、缺口、修改建议 | Java/规则校验结构和敏感内容 |
| 岗位匹配 | 学生画像、岗位 JD、规则分 | 推荐解释、准备建议 | Java 计算基础分，Agent 只解释 |
| 面试训练 | 简历、岗位、轮次 | 问题、评分、训练报告 | 固定评分维度和结果格式 |
| 政策问答 | 用户问题、政策知识库 | 带来源答案 | RAG 引用、无来源时拒答 |
| 就业分析 | 报表指标、风险数据 | 趋势和管理建议 | 指标由报表/Java 聚合提供 |

## 3. 数据流

1. 用户在低代码页面或 KWC 组件发起操作；
2. 权限模型判断数据域和操作权；
3. 表单/流程模型记录业务状态；
4. 服务模型调用 Java 插件或 AI 工具；
5. Java 负责确定性计算、校验、审计与结果落库；
6. 报表模型聚合业务数据，KWC 负责复杂可视化；
7. Agent 读取经过授权的数据或知识库，输出解释性结果。

## 4. 安全与隐私

- 仅使用模拟学生、企业、岗位和政策数据；
- 角色权限按最小授权原则配置；
- KWC 不持久化平台 Token，不在浏览器日志输出敏感数据；
- Java 服务端统一管理密钥、调用超时、重试和脱敏；
- Agent 工具调用必须经过服务模型或 Java 权限校验；
- 导出演示材料前检查租户、用户、URL、Token 和真实姓名。

## 5. 可审查交付物

- `platform/model-inventory.md` 与平台实际模型一一对应；
- `platform/exports/` 保存允许提交的模型导出物；
- `platform/kwc/` 和 `platform/java/` 只接收官方脚手架生成并可验证的源码；
- `platform/ai/` 保存提示词、知识库清单、工具协议和评测样例；
- 答辩材料应包含平台应用、模型、流程、权限、报表、Agent、KWC 和 Java 插件的截图或录屏证据。
