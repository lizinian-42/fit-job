# Fit Job 苍穹低代码与 KWC 视觉规范

## 1. 目标

- **可信**：高校就业服务需要清晰、稳健、可解释；
- **统一**：低代码页面与 KWC 组件共享颜色、字号、间距和状态语言；
- **克制**：优先使用平台标准控件，不用自定义组件重造所有页面；
- **可答辩**：关键状态、匹配依据、流程节点和数据来源能被快速看懂。

## 2. 页面承载原则

| 场景 | 首选实现 |
| --- | --- |
| 学生档案、岗位、申请、日志、评价 | 苍穹表单/列表模型与标准控件 |
| 审批进度、状态流转 | 苍穹流程模型和流程记录控件 |
| 常规统计和明细报表 | 苍穹报表模型 |
| 六维匹配、诊断结果、复杂图表 | KWC 组件 |
| 多轮面试、流式回答、组合驾驶舱 | KWC 组件 + 服务模型 |

## 3. 视觉语言

- 背景：冷白或平台默认浅色主题；
- 主文字：深蓝灰，保证长文本阅读；
- 主色：蓝色，用于主操作、选中态和关键指标；
- 辅助色：青色，用于可视化对比；
- 成功态：绿色；警告态：橙色；错误态：红色；
- 圆角、阴影和间距优先复用平台主题变量；
- KWC 不应覆盖全局主题，只在组件作用域内扩展变量。

## 4. 组件映射

| 设计语义 | 低代码/KWC 实现建议 |
| --- | --- |
| 主按钮/次按钮 | 平台标准按钮，KWC 仅补充复杂交互动作 |
| 状态标签 | 平台状态字段、枚举样式或 KWC Badge |
| 指标卡 | 报表指标 + KWC 组合卡片 |
| 时间线 | 流程记录优先，跨模型叙事再使用 KWC 时间线 |
| 空状态 | 平台空状态规范，提供明确下一步操作 |
| 六维匹配图 | KWC 可视化组件，分值由 Java/服务模型提供 |
| 驾驶舱 | 报表模型提供数据，KWC 负责复杂布局与交互 |

## 5. 交互与可访问性

- 所有操作必须有加载、成功、失败和无权限状态；
- 颜色不能是唯一状态提示，同时提供文字或图标；
- KWC 键盘焦点、弹窗关闭和表单错误提示必须可用；
- 学生端保持低密度，管理端可提高信息密度但不得牺牲可读性；
- 适配平台常用桌面分辨率，并验证窄窗口下不出现水平溢出；
- AI 结果必须展示生成时间、输入范围、来源或解释说明。

## 6. 设计验收

每个页面或 KWC 组件需保存：

1. 设计意图和使用角色；
2. 对应表单/服务/流程/报表模型编码；
3. 正常、空、错误、无权限状态截图；
4. KWC 与低代码页面的主题一致性截图；
5. 关键交互录屏或步骤说明。

本规范不再维护 React、Tailwind、Radix 或 Vite 组件实现。
