# Fit Job 本地协作与平台开发说明

## 1. 重要说明

Fit Job 不是可脱离金蝶 AI 苍穹平台独立运行的 React 项目。完整产品需要目标苍穹租户、开发应用、低代码模型、KWC 工程、Java 扩展和 AI 智能知识引擎共同运行。

仓库的作用是保存：

- 模型清单和架构决策；
- 苍穹平台允许导出的配置；
- 官方脚手架生成的 KWC 源码；
- 官方模板生成的 Java 插件/服务源码；
- Agent、RAG、工具协议、模拟数据和评测资产；
- 可复核的截图、录屏说明和交付文档。

## 2. 必需条件

| 条件 | 要求 |
| --- | --- |
| 苍穹平台 | 可访问的开发租户、应用与开发权限 |
| 低代码能力 | 可创建表单、服务、流程、报表、权限模型 |
| KWC | 使用目标平台版本对应的官方文档、依赖和脚手架 |
| Java | 使用目标平台支持的 JDK 与构建工具版本 |
| Git | 用于源码、导出物和文档协作 |

不要在未确认目标平台版本前自行固定 KWC、JDK、Maven 或 Gradle 版本。

## 3. 首次准备

1. 在苍穹平台创建或确认 Fit Job 应用；
2. 将 `platform/app-manifest.example.yaml` 复制为 `platform/app-manifest.local.yaml`；
3. 填写应用编码、环境、平台版本和模型编码，不填写 Token 或密码；
4. 按 `platform/model-inventory.md` 创建最小模型集；
5. 从目标平台官方入口生成 KWC 和 Java 工程；
6. 将生成的源码分别放入 `platform/kwc/` 与 `platform/java/`；
7. 将可提交的模型导出物放入 `platform/exports/`。

## 4. KWC 开发规则

- 正式前端只能使用苍穹低代码页面与 KWC；
- 标准增删改查、审批和权限页面优先由低代码模型完成；
- KWC 用于六维匹配图、复杂诊断面板、面试交互和驾驶舱组合组件；
- KWC 工程必须来自目标平台版本的官方脚手架，仓库不手写猜测性的依赖清单；
- 构建、调试、发布命令以脚手架 README 和苍穹开发者文档为准；
- KWC 与平台的数据交互必须走平台支持的服务模型或 API，不建立绕过权限的私有数据通道。

## 5. Java 开发规则

- Java 工程必须基于苍穹官方插件/服务模板；
- JDK 与构建工具版本以目标环境兼容矩阵为准；
- 复杂评分、风险规则、AI 调用封装和数据聚合放在 Java；
- 权限、审批和主业务状态仍由苍穹模型控制；
- 密钥只保存在平台密钥管理或本机私有配置中；
- Java 单元测试应覆盖评分边界、状态校验、幂等和异常降级。

## 6. 验证清单

提交前至少确认：

- [ ] 仓库不存在 React/Vite 正式前端工程；
- [ ] 模型清单与平台实际编码一致；
- [ ] 四类角色权限分别验证；
- [ ] 实习申请流程可从发起走到归档；
- [ ] KWC 组件在苍穹页面内加载且无越权请求；
- [ ] Java 插件可在目标环境编译、部署和回滚；
- [ ] Agent 输出包含来源或可解释信息；
- [ ] 演示数据全部为模拟数据；
- [ ] 导出物、截图和录屏不包含密钥与真实个人信息。

仓库基线检查：

```powershell
.\scripts\check-environment.ps1
```

该脚本只检查仓库结构、Git 和可选 Java 工具。苍穹平台权限、模型配置、KWC 发布和 Java 部署必须在目标环境中人工或通过平台工具验证。

## 7. 私有配置

- `platform/app-manifest.local.yaml` 只保存本机非敏感标识，已被 Git 忽略；
- `.env*`、Token、密码、租户密钥和真实学生数据不得提交；
- 需要共享的字段只写入 `platform/app-manifest.example.yaml`，值使用占位符。
