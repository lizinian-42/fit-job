# M1 阶段总结

## 当前阶段

M1 已完成 KWC 可运行原型、匿名 Mock 数据、完整演示导航和静态部署链路。演示从首页开始，依次覆盖学生工作台、简历诊断、岗位推荐、AI 面试、政策问答和就业驾驶舱。

## 已完成

- 7 个可访问的 KWC 页面与对应苍穹页面元数据。
- 覆盖学生、企业、岗位、简历/诊断、求职/实习申请、面试、驾驶舱和政策问答的 10 组匿名 Mock 数据契约。
- 首页、hash 路由、全局导航和逐页上一步/下一步入口。
- 三轮 Mock 面试、实时评分和四维面试报告。
- 独立静态预览构建与 GitHub Pages workflow。
- ESLint、Mock 数据校验、KWC 生产构建和桌面/移动端 Playwright 验收。

## 当前困难

- KWC 默认生产构建面向苍穹组件发布，会外置运行时；静态预览需要单独打包完整运行时并使用相对资源路径。
- 当前尚未接入目标苍穹租户，页面元数据、表单 ID、权限和发布流程仍需在比赛环境验证。
- AI 简历诊断、岗位匹配、面试报告与政策问答目前是结构化 Mock 输出，尚未连接 Agent、RAG 和 Java 服务。
- 本地 Git HTTPS 偶发连接重置，远端分支同步使用 GitHub API 作为降级通道；不影响代码内容和 PR 基线。

## 下一阶段

M2 聚焦苍穹低代码业务模型和 AI 能力对接：

1. 建立学生档案、岗位、申请、面试、政策和就业指标模型。
2. 对接四角色权限与实习申请流程。
3. 将 Mock DTO 替换为 Java 服务和 Agent JSON 输出。
4. 建立政策 RAG 知识库与来源校验。
5. 在目标苍穹环境验证 KWC 页面元数据、表单跳转和发布流程。

详细对接约定见 [M2 对接指南](./m2-integration-guide.md)，数据字段见 [M1 Mock 数据契约](./m1-mock-data-contract.md)。
